Build a Website with Gemini

No coding required. Three steps: create the homepage, expand into a full site, and maintain it safely over time.

Three things to understand first

① A website is just a collection of .html files

Every page you see on the web is a file sitting in a folder. A simple class website might look like this:

my-website/ ├── index.html ← homepage (always loaded first) ├── lesson1.html ← Unit 1 ├── lesson2.html ← Unit 2 └── images/ └── school.jpg ← image folder

When someone visits your site, the browser always opens index.html first. Other pages are reached through links.

② Gemini's Canvas mode is the tool we'll use

Gemini (gemini.google.com) has a feature called Canvas. It lets you write HTML on the left and see the live preview on the right — like writing in Word, but for web pages. We won't use the regular chat box today; everything happens inside Canvas.

How to open Canvas In the Gemini input bar, click the "Canvas" button. Or just type "Please use Canvas" at the start of your message — Gemini will switch automatically.

③ You are the designer. Gemini is your assistant.

Gemini cannot read your mind. The more specific your instructions (colors, layout, sections, fonts), the closer the result will be to what you actually want. Today's workshop is really about how to describe what you want.

1. Create your index page

The index page is the cover of your whole site. Get this right first, and everything else falls into place.

  1. Open Gemini and switch to Canvas mode Go to gemini.google.com, then click the "Canvas" button below the input bar.
  2. Copy the template prompt below and fill in the 【brackets】 with your own content Don't just say "make me a website." Tell Gemini what kind of website.
  3. Send the prompt. Wait for the live preview on the right Code on the left, rendered page on the right — both update together.
  4. Don't like something? Just say so in plain English "Make the title bigger." "Change the color to deep green." "Add more spacing between cards." It updates Canvas in place.
  5. Happy with it? Click "Download" or "Copy code" in the Canvas top-right Save the file as index.html. Done.

Ready-to-copy prompt

Please use Canvas. Write a single-file index.html (HTML + CSS) for me. 【TOPIC】 Homepage for a third-grade English class at OO Elementary School 【SECTIONS NEEDED】 1. A large hero with the school name and a short English slogan 2. A two-sentence welcome message 3. Three cards linking to three units: - Unit 1 - My Family (link to lesson1.html) - Unit 2 - My School (link to lesson2.html) - Unit 3 - My Hobbies (link to lesson3.html) 4. Footer with the teacher's name and school 【DESIGN】 - White background, warm orange accent (#F58220) - Friendly, readable fonts (Inter or similar) - Large text — readers are young students - Must work on mobile (responsive) Output a complete single-file HTML with the CSS inside a <style> tag.
Why this works Four things are clearly defined: topic, sections, design style, and technical requirements (single file, responsive). With this level of detail, Gemini's first draft is usually 80% there.

2. Expand into a full site

Once the homepage exists, build out each linked page one at a time. The golden rule: one page per request — never ask Gemini to write the whole site in one go.

  1. Stay in the same Canvas conversation and ask for the next page Gemini remembers the homepage's design, so it will reuse the colors, fonts, and layout automatically.
  2. Save each finished page with the matching filename lesson1.html, lesson2.html, etc. Filenames must match exactly what the homepage links to.
  3. Use placeholders for images; add real photos yourself Gemini doesn't generate images. Take or find them, name them clearly, and put them in an images/ folder.
  4. After each page, double-click the .html file to preview in your browser It opens directly — no internet needed. Check the layout and verify links work.

Ready-to-copy prompt (subpage)

Please reuse the same design and colors from index.html. Write lesson1.html (single file, HTML + CSS). 【TOPIC】 Unit 1 - My Family 【SECTIONS NEEDED】 1. At the top, a "back to home" link: <a href="index.html">← Back to Home</a> 2. A two-sentence unit intro 3. Five vocabulary cards in a row, each containing: - English word (large) - One emoji Words: father 👨 / mother 👩 / brother 👦 / sister 👧 / pet 🐶 4. A featured sentence: "This is my family." (large, centered) 5. Same footer as index.html Output the complete single-file HTML.
Tip for workshop teachers Most lesson pages share the same skeleton (intro → vocabulary cards → example sentence → back link). Once your first lesson page is right, you can produce the rest with very short prompts: "Same structure, but topic is My School. Words: classroom, teacher, library, playground, friend." Gemini handles the rest.

3. Maintaining your site safely

This is where most teachers run into trouble. Memorize this one rule:

The maintenance mantra "Change only X. Leave everything else alone. Output the full file."

The five-step safe edit

  1. Back up first Duplicate the file you're about to edit (e.g. lesson1.html → lesson1_backup.html). If something breaks, you have a way home.
  2. Open the original in a text editor and select all Mac TextEdit: Cmd+A then Cmd+C. Windows Notepad: Ctrl+A then Ctrl+C.
  3. In Gemini Canvas, paste the full source first, then describe the change Order matters: let Gemini see the current state before you tell it what to change.
  4. Be specific and set boundaries in your prompt Say exactly what to change, what NOT to touch, and ask for the complete new file (not just the changed section).
  5. Replace the original, preview in browser, then upload Only push to GitHub after the browser preview looks correct.

Ready-to-copy prompt (editing an existing page)

Below is my current lesson1.html. Please do ONE thing only: change the emoji on the "father" card from 👨 to 👨‍🦱. 【STRICT RULES】 - Everything else — content, design, CSS, comments — must stay exactly as it is - Do NOT reformat, do NOT "optimize," do NOT simplify my code - Output the complete new HTML, including all unchanged parts, so I can replace the original file directly Here is the original HTML: (paste your entire lesson1.html here)

Common mistakes vs. the right way

✗ Wrong

"Update the vocabulary cards on lesson1 for me."

→ Gemini will improvise freely and often rewrites parts of your design you wanted to keep.

✓ Right

"Change only the third card: word from 'brother' to 'grandfather', emoji to 👴. Everything else unchanged. Output the full HTML."

✗ Wrong

Pasting only a snippet of code and hoping Gemini will "fill in the rest"

→ It will invent the missing parts, and your original file gets silently simplified.

✓ Right

Paste the entire current source, specify the change clearly, and require "output the complete file"

✗ Wrong

No backup. You edit directly. Something breaks. You have no way back.

✓ Right

Duplicate the file before any edit. Name it _backup. Replace the original only after verifying the new version.

Tip for workshop teachers The most common disaster is "I wanted to change one tiny thing, and the AI redid the entire page." Bake these three phrases into every edit prompt — "change only X, leave the rest alone, output the full file" — and you'll avoid 95% of accidents.

4. Publish on GitHub

You have your files, but they live on your computer — only you can see them. GitHub is a free "cloud drive + auto-hosting" service: drop a folder with index.html in it, and GitHub turns it into a real website anyone in the world can visit.

① Create your free GitHub account (3 minutes)

  1. Go to github.com and click the green "Sign up" button
  2. Use a personal email — not your school address School emails often block third-party verification mail.
  3. Pick a username Short, lowercase, no spaces. This becomes part of your URL: username.github.io. Use your real name or a short identifier — don't pick "sarah-english-teacher-2026."
  4. Set a password → click the verification email link Done.

② Create your first repository

A repository (repo) is just GitHub's word for a folder. To host a website, you need a repo to hold the files.

  1. After logging in, click the "+" in the top-right → New repository
  2. Name your repo Lowercase, hyphenated. Examples: my-classroom, english-portfolio, grade3-english. The name shows up in your URL — pick carefully, it's hard to change.
  3. Set visibility to Public Free GitHub Pages only supports Public repos. Don't worry — only the HTML you upload is visible. Your email and password stay private.
  4. Tick "Add a README file" Optional, but recommended — keeps the repo from being empty.
  5. Click the green "Create repository" button You now have a cloud folder ready for your files.

③ Upload your index.html

  1. Open your new repo on github.com
  2. Click "Add file" → "Upload files" Just above the file list.
  3. Drag your index.html onto the dashed upload area Or click to browse. If you have an images/ folder, drag that too.
  4. Scroll down and click the green "Commit changes" button Your file is now in the repo.

④ Turn on GitHub Pages

At this point your files are in the cloud, but the website isn't live yet. GitHub Pages is the free hosting feature — you have to switch it on manually.

  1. In your repo, click the "Settings" tab At the right end of the tabs row.
  2. In the left sidebar, scroll down and click "Pages"
  3. Under "Source," choose "Deploy from a branch" Branch = main, folder = / (root).
  4. Click "Save" and wait about a minute
  5. Refresh the page — a green banner appears with your live URL It looks like: https://username.github.io/my-classroom. That's your website — anyone in the world can open it.

⑤ Share your URL

Just send the link in email, group chat, on a flyer, or in a school newsletter. Students, parents, the principal — anyone with the URL can open it in any browser. No login, no install, no app required.

How to update your site later Go to the same repo → "Add file" → "Upload files" → drag the new index.html on top of the old one (GitHub recognizes the same filename and replaces it). The live site refreshes in about a minute. Combine this with the maintenance discipline from Section 3 and you have a complete workflow.

5. Bonus: Buy a custom domain & set up DNS with Gemini's help

Want www.mrwang-english.com instead of username.github.io/my-classroom? You can — for about US$10–15 per year. The domain stays yours as long as you keep renewing.

This section is optional — the free github.io URL is perfectly fine for years. Come back to this when you're ready to upgrade.

② Tell GitHub about your custom domain

  1. Go to your repo → Settings → Pages
  2. Enter your domain in the "Custom domain" field Example: www.mrwang-english.com
  3. Click Save That's GitHub's side done. Next, the registrar.

③ Add DNS records at your registrar

DNS records are how the internet knows "this domain should point to GitHub's servers." Log in to wherever you bought the domain and add these five records:

TypeHostValue
CNAMEwwwusername.github.io
A@185.199.108.153
A@185.199.109.153
A@185.199.110.153
A@185.199.111.153

Replace username with your actual GitHub username. After saving, wait 10 minutes to 24 hours for DNS to propagate.

④ Stuck? Ask Gemini to walk you through DNS

Every registrar has a different dashboard (Cloudflare, Namecheap, GoDaddy all look different). The easiest fix is to ask Gemini for click-by-click instructions for your specific registrar.

I just bought a domain at Cloudflare: mrwang-english.com My website is hosted on GitHub Pages: username.github.io/my-classroom (Replace "username" with your actual GitHub username.) Please walk me through, step by step: where exactly in the Cloudflare dashboard I click, which button to press, and what to type in each field to add these DNS records: - 1 CNAME record Host: www Value: username.github.io - 4 A records (pointing to GitHub's IPs) Host: @ Value: 185.199.108.153 / 109.153 / 110.153 / 111.153 Be concrete (which menu, which button, which field) — not just conceptual explanations. If I get stuck on a step, I'll ask follow-up questions.
The final step: HTTPS padlock Once DNS has propagated (1 hour to 1 day), go back to GitHub → Settings → Pages and you'll see an "Enforce HTTPS" checkbox. Tick it. Your site now shows the 🔒 padlock in browsers — looks like a real, professional site, and browsers stop showing "Not Secure" warnings.
Don't rush to buy a domain The most common trap for beginners: buying a domain before the website is even good. Better plan: use the free github.io URL for 3–6 months. Once you're sure you'll keep maintaining the site, then buy. If you forget to renew, someone else can snatch the domain — don't waste the money.

The mindset that makes it work

  • Be specific. Topic, sections, color, fonts — spell it all out. Don't make the AI guess.
  • One change at a time. Don't ask for a whole site in one prompt, and don't make five edits at once.
  • Always back up. HTML files are tiny. There's no excuse not to keep copies.
  • When editing, always say "leave everything else alone, output the full file." This single phrase prevents most accidents.
  • The browser is your best testing tool. Double-click the .html — it opens immediately. Edit, preview, repeat.
  • AI is not magic. It is a capable assistant. You set the direction.
